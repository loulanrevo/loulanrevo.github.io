## GetQzonehistory-gui 增量获取体系重构

项目路径: `C:\Users\loulanRE\OneDrive\Desktop\GetQzonehistory-gui`

### 问题诊断
1. **说说文字增量补全次数过多**: `sync_messages` 调用 `fetch_all_messages`，后者每次都全量拉取列表+全量补全详情，即使本地已有完整内容
2. **重复"内容更新: 500字 -> 982字"日志**: `fetch_all_messages` 每次都从截断版列表内容开始重新补全详情
3. **存储问题**: `sync_messages` 只保存缓存状态(incremental_state.json)，不保存完整内容(qzone_data.json)，依赖 app.py 的 `save_full_data` 调用
4. **has_full_content 误报**: 详情 API 返回 `has_more_con=1` 时，即使内容已完整也标记 `has_full_content=False`，导致下次重复请求
5. **DetailDownloader 不持久化**: 手动补全页面修改内存中的消息但不保存到 qzone_data.json，关闭后丢失
6. **两套系统不同步**: IncrementalDownloader 和 DetailDownloader 有各自独立的进度追踪

### 修改的文件
- `app/api/qzone.py`: 新增 `fetch_message_list_only()` (仅列表不补详情); 修复 `_apply_detail_content()` 的完整性判定
- `app/services/incremental_downloader.py`: 重构 `sync_messages` 为真正增量; 新增 `_fetch_and_apply_details()`; 新增 `_save_messages_preserving_friends()` 和 `_save_board_messages_preserving()`; CachedMessage 增加 `content_length` 字段; 重写 `_find_changed_messages` 对比逻辑
- `app/services/detail_downloader.py`: 新增 `_persist_data()` 和 `_update_incremental_cache()`; 每条详情补全后立即持久化

### 核心改进
- 增量同步使用 `fetch_message_list_only` 仅拉列表，不再全量补详情
- 本地已有完整内容(content_length >= 列表长度 且 has_full)的消息直接跳过详情请求
- 详情补全后立即保存到 qzone_data.json (保留好友数据)
- 详情内容与列表内容长度差 <= 5 字符时，判定为格式差异，标记为完整(修复 has_more_con 误报)
- DetailDownloader 补全后同步更新 incremental_state.json 缓存
- 向后兼容旧版 state 文件(无 content_length 字段时默认为 0)

### 验证结果
- 3轮模拟测试: 第1轮补全(500->982), 第2轮确认(982==982, 标记full=True), 第3轮完全跳过
- DetailDownloader + 缓存同步测试通过
- 旧格式向后兼容测试通过

## 2026-07-12 补充：修复请求格式校验死循环（关键根因）

### 问题
日志分析发现：从 2026-05-31 到 2026-07-12 的**每一次运行**都显示
`[WARNING] 说说请求格式已变更` + `请求格式变更，执行全量同步`，
导致 `has_local=False`，每次都被当作"首次同步"全量补全 17 条详情。

### 根因
`_validate_request_formats` 同时校验 msg 和 board 两种格式，但：
- `sync_messages` 调用时传 `(msg_formats, [])` — board 为空
- `sync_board_messages` 调用时传 `([], board_formats)` — msg 为空
两者互相覆盖存储文件，形成死循环：每次都判定格式不匹配 → 全量同步。

用户的 `request_formats.json` 实际状态：`message_formats: []`（被 board 同步覆盖为空）。

### 修复（`incremental_downloader.py` `_validate_request_formats`）
1. 空列表表示"本次不校验该类型"，跳过比对
2. 存储为空但当前非空时，判定为"旧版bug残留"，自动修复而非触发全量同步
3. 保存时保留未变更类型的已存储值，避免互相覆盖

### 验证
- 模拟用户实际 buggy 状态文件测试：首次运行即恢复增量模式（无需二次运行）
- 后续运行持续稳定增量
